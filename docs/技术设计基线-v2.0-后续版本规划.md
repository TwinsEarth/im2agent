## 2. 架构演进蓝图（分层视图）

```
┌─────────────────────────────────────────────────────────────┐
│ L1 接入层   耳机/眼镜(BLE) · 手机 · PC · 手表 · Web            │
├─────────────────────────────────────────────────────────────┤
│ L2 端侧     唤醒词 · 意图粗分类 · 敏感前置过滤 · 离线审批缓存   │
│            （原始音频不出端，可验证承诺）                        │
├──────────────┬──────────────────┬───────────────────────────┤
│ ① 人类 IM    │ ② Agent 协商      │ ③ 审批/审计事件流           │
│ 腾讯云 IM    │ 双向流+8态机      │ Kafka（现内存 Bus）         │
│ WebSocket    │ 熔断/审批卡片     │ 与业务消息物理隔离           │
├──────────────┴──────────────────┴───────────────────────────┤
│ L4 编排层   总Agent → 子Agent矩阵 → 门控 → 审批 → Skill(MCP)  │
│            ↑ 记忆分层 + 蒸馏闭环（v0.6/v0.7 新增）             │
├─────────────────────────────────────────────────────────────┤
│ L5 模型层   端侧小模型(唤醒/过滤) ↕ 云端大模型(规划/协商/推理) │
│            Model Router：规则优先，LLM 增强，可降级（v0.8）      │
├─────────────────────────────────────────────────────────────┤
│ L6 数据层   PG(pgvector) · OpenSearch · Kafka · 对象存储 · WORM│
│            Context 本地加密优先（v1.0 数据主权）                │
└─────────────────────────────────────────────────────────────┘
```

### 关键设计原则（沿用并强化）

1. **代码层门控，不靠提示词**：所有信任边界在 PreToolUse 强制执行，LLM 只负责“决策建议”，不负责“权限授予”。
2. **规则优先、LLM 增强、可降级**：任何 LLM 不可用时，系统退回规则引擎仍可跑通核心链路（自测不依赖网络/模型）。
3. **Context 是核心资产**：模型可租、Context 不可租；记忆分用户/分 Agent 隔离，随用户迁移。
4. **离线可编译可自测**：延续 stdlib-only，LLM/Kafka/IM 全部走接口 + 内存桩，门禁不依赖外部服务。
5. **三条流量物理隔离**：IM、协商、事件三条通道独立存储、独立扩缩、独立审计。

## 4. 各版本详细设计

### v0.6 · Context 基座（最高优先级）

**为什么最先做**：Context 飞轮是第一护城河，也是后续 LLM、蒸馏、客户端的共同依赖。

**新增模块**：

| 包 | 职责 |
|---|---|
| `internal/memory` | 记忆层统一接口（Working/Episodic/Semantic） |
| `internal/memory/working` | 工作记忆：当前任务上下文（短 TTL、会话级） |
| `internal/memory/episodic` | 情景记忆：办事轨迹/审批历史（时间线、追加写） |
| `internal/memory/semantic` | 语义记忆：偏好/底线/习惯（可检索、可蒸馏） |
| `internal/memory/memory_memory.go` | 内存实现（默认，离线自测） |

**核心接口**：

```go
type MemoryStore interface {
    // Working：当前会话/任务的临时上下文
    PutWorking(ctx, agentID, key string, v any) error
    GetWorking(ctx, agentID, key string) (any, error)
    // Episodic：追加一段经历（办事轨迹、审批事件）
    AppendEpisode(ctx, agentID string, e *Episode) error
    ListEpisodes(ctx, agentID string, q Query) ([]*Episode, error)
    // Semantic：沉淀偏好/底线（key 语义化，带置信度与来源）
    UpsertFact(ctx, agentID string, f *Fact) error
    SearchFacts(ctx, agentID string, q string) ([]*Fact, error)
}
```

**隔离规则**：记忆按 `userID + agentID` 双键命名空间；子 Agent 只读写自己的记忆，跨 Agent 读必须经总 Agent 授权（复用 Capability 门控）。

**验收**：`memory` 包单测；总 Agent 可给“采购子 Agent”写偏好、读轨迹；跨 Agent 越权读被门控拒绝；`make gate` 全绿。

### v0.7 · 蒸馏闭环

**目标**：把人的每次审批/驳回/修改，沉淀成“下次更准”的阈值，不改基座模型。

**新增模块**：

| 包 | 职责 |
|---|---|
| `internal/distill` | 反馈收集 → 规则归纳 → 阈值建议 |
| `internal/memory/improvement` | Improvement Memory（结构化反馈账本） |

**机制**：

```
用户决策（通过/驳回/修改）
   → 写 ImprovementRecord（原决策、人给的边界、结果）
   → distill 归纳：同类场景的金额阈值/时间段/可信对象
   → 生成 ThresholdPatch（建议值 + 置信度 + 证据链）
   → 高置信自动收紧 / 低置信推送“建议审批卡片”
   → 子 Agent 决策阈值更新（只动配置，不动模型）
```

**护栏**：阈值只能“收紧”不能“放宽”自动执行；放宽必须人来批；保留版本与回滚。

**验收**：连续 3 次驳回“夜间采购>¥500”后，系统自动把该子 Agent 的夜间采购阈值收紧；放松阈值需人工审批。

---

### v0.8 · 云端模型接入（Model Router）

**目标**：让 Agent 具备规划/协商/专业推理，但保持可降级。

**新增模块**：

| 包 | 职责 |
|---|---|
| `internal/model` | Model Router 统一接口 |
| `internal/model/rule` | 规则引擎（默认，无 LLM 时的基线） |
| `internal/model/llm` | LLM Provider（OpenAI 兼容接口，可配 endpoint/key/model） |
| `internal/model/router` | 路由：意图分类→选规则或 LLM；超时/失败回退规则 |

**接口**：

```go
type Model interface {
    Plan(ctx, task string, ctxFacts []*Fact) (*Plan, error)
    Negotiate(ctx, in *NegotiationTurn) (*NegotiationTurn, error)
    Classify(ctx, text string) (*Intent, error)
}
```

**硬约束**：
- LLM 输出只作“建议”，落任何动作前仍过门控/审批；
- 结构化输出（JSON schema），解析失败回退规则；
- Provider 配置走环境变量，`LLM_DSN` 为空时纯规则，自测零外部依赖；
- 敏感内容（手机号/金额/地址）在出端前脱敏，可配置。

**验收**：配置 LLM 时采购子 Agent 能多步规划；断开 LLM 后自动退回规则，7 服务自测仍全绿。

---

### v0.9 · 陌生人付费完整链路

**目标**：贯通“付费永远发生在 Agent 预审之后”。

**编排**：

```
陌生人来意
 → 合规护栏（已有）
 → Agent 意图预审（LLM/规则）
   ├─ 拒绝：返回结构化拒绝，不进付费
   └─ 通过：生成来意卡片 + 定价（发送即扣费 / 回复才扣费）
 → 扣费/冻结（复用 ledger，message_id 幂等）
 → 接收方 Agent 摘要 → 人决定是否看
 → 回复才扣费模式：未回复自动退款
```

**新增**：定价配置（用户按信任档/时段定价）、来意模板、冻结/解冻账本操作、完整链路 API 与自测。

**验收**：垃圾来意预审即拒不扣费；正常来意付费后可查看；回复才扣费模式未回复自动退款。

---

### v0.10 · Agent 协商双向流

**目标**：把 HTTP 一问一答升级为实时双向流，终止时只推一张审批卡片。

**方案**：优先 **WebSocket**（stdlib 友好，`golang.org/x/net/websocket` 或自研 RFC6455），gRPC 作为生产可选。沿用现有 8 态状态机，仅替换传输层。

**新增**：`internal/stream`（连接管理 + 房间/会话 + 断线重放）、状态变更事件推送、熔断实时通知。

**验收**：两个 Agent 双流协商，3 轮达成推一张卡片；6 轮熔断推失败卡片；断线后事件可重放。

---

### v0.11 · 生产存储与事件（PG + pgvector + Kafka）

**目标**：把内存记忆/事件落到生产存储，支撑语义检索与合规追溯。

**新增**：
- PG 表：`working_memory` / `episodes` / `facts` / `improvements` / `messages`；
- pgvector：事实语义向量检索（`facts.embedding`）；
- Kafka 适配：`internal/eventbus` 增加 Kafka 实现（接口不变，内存/Kafka 可切换）；
- 迁移脚本 + 回放工具。

**验收**：`PG_DSN` 配置后记忆/事件落 PG；断 PG 回退内存；向量检索返回相关事实。

---

### v0.12 · 人类 IM 通道（腾讯云 IM）

**目标**：人类情感消息走腾讯云 IM，关系/账本/审计在自有后端，双通道隔离。

**新增**：`internal/im` 适配层（IMProvider 接口 + 腾讯云实现 + 内存桩）、UserSig 签发服务、Webhook 回调（消息/已读/群事件）、与 Agent 通道的路由判定（消息类型分流）。

**验收**：人类消息进 IM 通道、Agent 协商进流通道、审批事件进 Kafka，三者互不串流。

### v0.13–v0.15 · 客户端、端侧、手表

- **v0.13 客户端**：Flutter 完整审批卡片流（通过/修改/驳回/升级）、巡视态工作日志、Agent 摘要 IM；PC 端（Flutter Desktop/Go Wails 二选一）。

## 5. 技术选型与框架（决策）

| 领域 | 选型 | 理由 |
|---|---|---|
| 后端 | Go + net/http（现状），WebSocket 替代 gRPC 先行 | stdlib 友好、离线可测、部署简单 |
| 模型 | OpenAI 兼容接口（可换任意云/本地模型） | 不绑死厂商；本地模型可走 Ollama |
| 检索 | pgvector | 与 PG 共库，少一个基础设施 |
| 消息/事件 | 人类 IM=腾讯云；Agent 协商=自研流；审计=Kafka | 三流量物理隔离 |
| 端侧 | 端侧服务可插拔（规则/小模型），手机做 BLE 网关 | 原始音频不出端 |
| 客户端 | Flutter（手机/PC/手表统一） | 一套 Dart 三端 |
| 加密 | 信封加密（AES-GCM + 设备公钥） | 本地加密优先 |
| 部署 | 单机二进制（演示）+ docker-compose（生产） | 私有化友好 |

## 6. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| LLM 幻觉导致越权 | 高 | 门控不交给模型；LLM 仅建议；结构化输出 + 规则兜底 |
| 蒸馏误收紧导致 Agent 变笨 | 中 | 只收紧不自动放宽；阈值版本化、可回滚、带证据 |
| 隐私泄露（原始音频/敏感词） | 高 | 端侧过滤；出端脱敏；“不出端”可审计证明 |
| 双通道串流 | 中 | 独立路由 + 独立存储 + 链路追踪染色 |
| 外部依赖（Kafka/IM/LLM）不可用 | 中 | 全接口内存桩，门禁离线可跑 |
| Context 迁移锁定 | 中 | 标准化导出格式 + 加密包，v1.0 承诺可移植 |
| 付费争议（退款/日限） | 中 | 不可变账本 + message_id 幂等 + 自动退款对账 |
